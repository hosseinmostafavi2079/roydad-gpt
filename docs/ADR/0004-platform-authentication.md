# ADR 0004: Use server-managed platform admin authentication

- **Status:** Accepted
- **Context:** Platform administrators can create tenants and use database provisioning, so their identity boundary is separate and higher risk than future tenant authentication. Passwords require Argon2id, sessions must be revocable, and production platform administrators require stronger authentication.
- **Decision:** Use Better Auth with PostgreSQL-backed sessions, its TOTP two-factor plugin, Argon2id through the supported password hash/verify hooks, no public sign-up, secure cookie/origin/CSRF protections, server-side role checks, and database-backed throttling. Require completed TOTP for platform authorization in production. Bootstrap the first synthetic development admin through a guarded command; no secret is committed. Add reviewed forward migrations for plugin tables whose create paths rely on database-generated text IDs. Keep unexpected auth exceptions inside the route boundary and emit only safe error metadata.
- **Consequences:** Better Auth migration output and password hashing configuration require review. Production first-admin/MFA enrollment and recovery need a controlled runbook. MFA enrollment lives outside the administration layout to avoid a redirect loop while preserving its server-side administrator check. Auth configuration is isolated from future tenant RBAC.
- **References:** [Better Auth Next.js integration](https://better-auth.com/docs/integrations/next), [Better Auth password options](https://better-auth.com/docs/reference/options), [Better Auth two-factor plugin](https://better-auth.com/docs/plugins/2fa).
